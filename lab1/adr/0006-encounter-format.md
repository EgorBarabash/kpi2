# ADR 0006: Формат зустрічі — атрибут Encounter.max_matches

**Статус:** Прийнято

**Контекст:** README описує зустрічі у форматі BO1/BO3/BO5, але в моделі (коміт (https://github.com/EgorBarabash/kpi2/commit/5c92f9ca8dda45422194c8146d05eb6e9029ceab)) Encounter не мав формату, тож кількість матчів у зустрічі нічим не обмежувалася.

**Рішення:** Атрибут max_matches (int) у Encounter зі значеннями 1, 3 або 5. Бізнес-правило у зв'язку 8: зустріч має не більше max_matches матчів, map_order від 1 до max_matches.

**Розглянуті альтернативи:**
- *Не зберігати формат, рахувати матчі* — відхилено: формат потрібно знати до початку, а запланована зустріч ще не має матчів.
- *Enum bo_format (bo1, bo3, bo5)* — відхилено: правило порівнює map_order з числом, а кількості за критерієм 7 мають тип int.
- *Формат на рівні Tournament* — відхилено: у межах турніру формат може відрізнятися (групи BO1, фінал BO5).

**Наслідки:**
- Формат задається для кожної зустрічі окремо.
- Обмеження кількості матчів і допустимі значення 1/3/5 не видно на діаграмі — це бізнес-правило в spec.
